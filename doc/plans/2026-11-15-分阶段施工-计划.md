# 分阶段施工计划

> 给接手的 agent 看的施工图。当前做到哪看 `doc/0-ROADMAP.md`，本文件只讲每个阶段做什么、怎么派、怎么验。

## 总原则

- **每个阶段结束都是一个能玩的完整状态**。额度用完停在任何一个阶段后面，都不算半成品。
- **协调线程只做三件事**：写规格、验收、回写文档。写代码的活派给子代理。
- **省钱的派法**：
  - 阶段一（引擎 + 第 1 章）是地基，定手感和画面基调，派 Opus 子代理做一次做扎实。
  - 阶段二到六（各章内容）是照着引擎契约和关卡规格施工，派 Sonnet 子代理。
  - 子代理只读自己那一章的规格 + 引擎契约，不读全仓。
- **并行规则**：两章可以同时做，前提是各自只动自己的 `src/chapters/chN-*/` 目录、各用各的端口、各用各的浏览器标签页。
  子代理不提交 git，由协调线程验收后统一提交。

## 通用验收（每个阶段都要过）

子代理自验，协调线程复验：

1. `npm test` 全绿——本阶段新增的几何数学有测试。
2. `npm run build` 成功。
3. 本阶段每一关都能用 `/?level=<id>` 直接进；用正常操作能玩到过关；用 `window.__geo.complete()` 能强制过关（方便验收后续流程）。
4. 浏览器控制台没有报错。
5. 截图看过：1180×820（iPad 横屏）下不出滚动条、字看得清、按钮够大、画面不难看。
6. 没有任何打字输入框；没有红叉 / 扣分 / 倒计时。
7. 章节代码只在自己的目录里（S2 起）。

## 每阶段收尾（协调线程）

1. 复验上面七条。
2. 回写 `doc/0-ROADMAP.md`：阶段状态、本阶段实际做成什么样、和规格不一样的地方、遗留问题。
3. 实现和规格不一样且实现更合理的，回改 `doc/levels/chN-*.md`；引擎接口变了回改 `doc/engine-contract.md` 与 `0-FRAMEWORK.md`。
4. `git commit`（一个阶段一个提交）。
5. 上下文过长就按 coordinator 协议换线程，新线程靠 ROADMAP 恢复。

## 派工单要点（每次派工都带上）

- 必读：`AGENTS.md`、`doc/0-FRAMEWORK.md`、本阶段的 `doc/levels/chN-*.md`、（S2 起）`doc/engine-contract.md`、
  `/Users/mao/Documents/Coding/Development/MyLibrary/core/rules/design-global.md`（改界面前必须读，否则会被拦）。
- 铁律：见 `AGENTS.md`「本项目特有规则」六条。
- 关卡规格是意图不是死命令：实现时发现某个玩法做出来别扭、或有明显更好的互动方式，可以改，但要在交付报告里写清「规格是什么、我改成了什么、为什么」。
  几何内容本身（这一关要让他发现什么）不许改。
- 自验：能用浏览器工具就新开一个标签页自己玩一遍并截图看；不能就明说「没有看过画面」。
- 交付报告：做了什么、每一关的自验结果、和规格不一样的地方、已知问题、建议提升到引擎的东西。

## 风险

| 风险 | 应对 |
|---|---|
| 3D 拖拽在触屏上手感差 | 引擎统一处理指针；每关都有「俯视」按钮；吸附要大方 |
| 子代理看不到画面，做出来难看 | 派工时要求用浏览器自验截图；协调线程每阶段亲自看 |
| 某一关玩法太复杂做不出来（3-6、5-4、6-6 风险最高） | 允许简化玩法，保住「要让他发现什么」；实在不行这关降级为演示 + 一个小互动 |
| 朗读在 iPad 上要先点一下才出声 | 首屏「开始」按钮里解锁语音 |
| 好不好玩机器验不了 | 每章做完就可以先给小野试，反馈记进 ROADMAP 的「试玩反馈」 |
